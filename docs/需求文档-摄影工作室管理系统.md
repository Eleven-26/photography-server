# SLOT 摄影工作室管理系统 — 后端需求文档

> 本文档汇总整个项目的需求与设计约定，作为项目开发与验收依据。
> 所属项目：photography-server（Go + Gin 后端） / 前端：SLOT PC 后台高保真可点击原型

---

## 一、项目总体说明

### 1.1 业务背景
服务于摄影工作室的 SaaS 管理系统，未来将面向 PC 管理后台、小程序管理后台、APP、H5 四大客户端。本次先实现后端基础能力与 PC 后台核心业务。

### 1.2 技术选型
- 后端语言/框架：Go + Gin（RPC 风格接口）
- 数据库：MySQL，库名 `photography`，字符集 `utf8`，排序规则 `utf8_general_ci`
- 前后端分离：后端 API 服务 + 前端静态站点
- 部署：Docker + Docker Compose（MySQL / 后端 / 前端三容器分离）

### 1.3 服务端接口风格
- 统一 RPC 风格：`POST /api/{客户端}/{模块}/{动作}[/:id]`
- 客户端分组前缀：`/pc`（管理后台）、`/miniapp`（小程序管理后台）、`/app`（APP）、`/h5`（移动端）
- 统一响应格式：
  ```json
  { "code": 0, "msg": "ok", "data": {} }
  ```
  `code=0` 表示成功；失败时返回业务错误码（`40000` 参数错误、`40100` 未登录、`40300` 无权限、`40400` 不存在、`40900` 冲突、`50000` 系统错误）。

### 1.4 安全与多租户
- 登录基于 JWT（HS256），令牌有效期默认 7 天。
- SaaS 多租户：所有业务表均含 `company_id`；未来扩展为"一公司多门店、多门店多管理员"，门店用 `store_id` 区分。

## 二、数据库设计规范

### 2.1 通用固定字段（每张业务表必备）
| 字段 | 类型 | 说明 |
| --- | --- | --- |
| created_by | BIGINT | 创建人 |
| created_at | DATETIME | 创建时间 |
| updated_by | BIGINT | 修改人 |
| updated_at | DATETIME | 修改时间 |
| deleted | BIGINT | 是否删除（软删除，0-否 1-是） |

另外每张业务表均含 `company_id`（公司 ID）。

### 2.2 建库要求
- 库名：`photography`
- 字符集：`utf8`，排序规则：`utf8_general_ci`
- 所有字段必须带中文备注（COMMENT）
- DDL / DML 脚本位于项目根目录 `docs/` 下：
  - `docs/sql/ddl.sql`：建库建表
  - `docs/sql/dml.sql`：初始化数据（公司/门店/角色/管理员/收款方式/示例套餐/客户/线索/报价）

### 2.3 数据表清单
- 系统：`sys_company`、`sys_store`、`sys_role`、`sys_user`、`sys_operation_log`、`sys_notification`
- 客户线索：`crm_customer`、`crm_lead`、`biz_quote`
- 套餐：`biz_package`
- 订单财务：`biz_order`、`biz_order_payment`、`biz_order_refund`、`biz_order_log`
- 交付作品：`biz_delivery`、`biz_delivery_item`、`biz_asset`
- 档期设置：`biz_calendar_block`、`biz_payment_method`、`biz_upload`

## 三、核心业务规则

### 3.1 金额与支付
- **定金**：按"基础套餐价 × 定金比例%"计算（`deposit_amt = base_price × deposit_rate / 100`）。
- **加选精修**：加选金额全部计入 **尾款**。
  - `尾款 = 基础价 - 定金 + 加选金额`
  - `订单总额 = 基础价 + 加选金额`
- 支付状态：待核验 → 已确认 / 已退款。
- 定金确认到账后，订单由"待定金"流转到"待拍摄"。

### 3.2 订单状态机
`待定金 → 待拍摄 → 拍摄中 → 精修中 → 待交付 → 已完成`；任意环节可 `取消`。
取消订单自动释放对应档期。

### 3.3 退款规则（按拍摄前小时数分档）
| 距离拍摄时间 | 可退比例 |
| --- | --- |
| ≥ 72 小时 | 100% |
| 48 ~ 72 小时 | 80% |
| 24 ~ 48 小时 | 50% |
| < 24 小时 | 0%（不可退） |

可退基数 = 已收定金（封顶订单定金），审核通过后累加订单已退金额，支付状态置为"已退款"。

### 3.4 交付（选片 / 精修）流程
`待上传样片 → 客户选片中 → 精修进行中 → 待确认交付 → 已交付`。
交付完成后可联动订单进入"已完成"。

### 3.5 套餐版本化
被订单引用过的套餐，若价格/内容发生实质变更，系统自动**生成新版本**（旧版本保留，新版本号 +1），保证历史订单快照一致性。

### 3.6 线索 / 客户流程
- 线索状态：待回复 → 待报价 → 已报价 → 已成交 / 已流失。
- 提供"线索转客户"（按手机号查重）、跟进记录、报价单生成。
- 报价单被接受后可一键下单（自动关联客户、套餐快照、锁定档期）。

## 五、部署说明

- 部署文件位于项目根目录：
  - `Dockerfile`（后端镜像，多阶段构建）
  - `docker-compose.yml`（MySQL + 后端 + 前端）
  - `deploy/nginx.conf`（前端 Nginx 配置，含 `/api` 反向代理）
- 前端镜像基于首页高保真原型构建静态站点（`frontend/`）。
- 默认账号：`admin` / `admin123456`（DML 或服务启动自动引导写入）。
