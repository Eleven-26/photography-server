## 七、有意约定（不视为缺陷）

- 三端 RPC 风格全 POST + 参数走 body + create/update 主键进 body：与后端契约强绑定，注释齐全。
- 前端不做 mock 回退、失败即清空数据：为了暴露故障，而非掩盖。
- 权限 fail-open（admin/未加载放行）：防止前后端版本不同步导致白屏，前提是后端强制鉴权。
- uni-app 无 router 目录（`pages.json` 声明路由）、自绘 AppTabBar、`.assets-raw/` 入库、不引 Prettier/UI 库。
- 后端 `presentation/bind` 暂留、`contract` 与 `pkg/*` 为中立层、业务层不 import infrastructure：均为既定分层决策。
