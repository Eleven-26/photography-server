# RBAC 权限点手册

> **权威来源**：权限点常量定义在 `internal/domain/perm.go`（代码），角色绑定关系在
> `docs/sql/增量/upgrade_role_permission_20260910.sql`（数据库种子）。本手册是查阅索引，
> 与代码不一致时**以代码与种子 SQL 为准**并回改本手册。

## 一、命名与判定规则

- 权限点格式：`{模块}:{动作}`，如 `order:view`、`payment:confirm`。
- **常量即权威**：每条业务路由必须挂 `mw.Perm(domain.PermXxx...)`，禁止在路由层写裸字符串。
- 判定链路：请求 → 认证中间件（加载角色授权）→ `admin` 角色码**短路放行全部权限** →
  逐一比对权限点 → 不满足返回 403。
- 字段级校验：同一接口内不同字段对应不同权限点时，用 `service.requirePerm`（当前唯一用例：
  `lead:update` 改 `owner_id` 需额外通过 `lead:assign`）。

## 三、内置角色默认权限

角色绑定关系的**唯一权威**是种子 SQL（INSERT 时 `JOIN sys_role ON code` 动态取 role_id，
不写死 ID，多租户安全）。当前各内置角色权限点数量：

| 角色 | code | 数量 | 说明 |
|---|---|---|---|
| 管理员 | `admin` | 70（全量） | **锁定不可改**，后端短路全放行 |
| 店长 | `manager` | 53 | 无 `payment:delete` / `package:delete` 等高危点（有意） |
| 摄影师 | `photographer` | 27 | 含 `lead:update` / `order:update` / `payment:create` / `settings:view`（2026-09-11 拍板补点） |
| 销售 | `sales` | 32 | 含 `request:handle` |

查某角色当前权限点：

```sql
SELECT rp.permission
FROM sys_role_permission rp
JOIN sys_role r ON r.id = rp.role_id
WHERE r.company_id = 1 AND r.code = 'photographer'
ORDER BY rp.permission;
```

> 注：`order:price` / `quote:audit` 已于 2026-09-11 移除——订单金额无独立修改接口（改价经
> 加项走 `order:update`），报价无审批接口。二期若落地相应接口，再按运维手册流程新增。

## 四、数据范围（data_scope）

权限点决定"能不能调这个接口"，数据范围决定"能看到哪些数据"。两者独立配置、正交生效。

| 值 | 含义 | 过滤规则（`internal/repository/scope.go`） |
|---|---|---|
| 1 | 全部数据 | 不加过滤 |
| 2 | 本门店 | 数据行 `store_id = 操作人.store_id` |
| 3 | 仅本人 | `photographer_id = 操作人` **或** `owner_id = 操作人`（取并集） |

硬规则（实现于 `applyScope` / `scopedOrder` / `scopedFromOrder`）：

1. **零值放行**：无操作人上下文（客户侧接口、定时任务、单元测试）不过滤。
2. **未分配门店降级**：本店用户 `store_id=0` → 按 `ScopeSelf` 过滤，而非看到全店。
3. **无 Owner 列的表** → `1 = 0`（返回空集，防止整表泄漏）。
4. **套餐（ScopeCols.Shared 共享资源）**：本店降级为本店 + 本人并集口径见 `scope.go` 注释。
5. **无 `store_id` 的从表**（收款/退款/加项/改期/评价/交付）：经
   `order_id IN (可见订单子查询)` 传递过滤，避免 JOIN 列名歧义与分页 COUNT 重复行。
6. **`admin` 短路**：数据范围对 admin 无效，恒为全部。

## 五、豁免权限点的接口（有意为之）

以下接口不挂权限点，任何登录员工可用：

| 接口 | 原因 |
|---|---|
| `/user/profile`、`/user/change-password`、`/user/logout` | 自助类：操作对象是登录者本人 |
| `/upload/file` | 通用上传能力，收款凭证/作品/交付多链路共用，挂点会误伤（如 sales 无 `asset:upload` 却要传收款凭证） |
| 员工端 `/device/*` 上报类 | 设备自助上报，非角色能力边界 |

## 六、前端权限映射

| 层级 | 机制 | 位置 |
|---|---|---|
| 路由级 | 路由 `meta.perm` + 全局守卫，无权限跳 `/403` | `src/router/index.ts` |
| 菜单级 | 侧边栏按 `hasPerm` 过滤，整组无权限整组隐藏 | `src/layouts/AppLayout.vue` |
| 按钮级 | `v-perm="'order:cancel'"` 指令，无权限移除元素 | `src/directives/perm.ts` |
| 逻辑判断 | `auth.hasPerm(x)` / `hasAnyPerm` / `hasAllPerm` | `src/stores/auth.ts` |

前端判定规则：`admin` 短路；用户未加载或后端未下发 `permissions` 时**默认放行**
（新旧前后端不同步发布不白屏）。
